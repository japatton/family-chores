# Ultra-review loop state

This file tracks findings across iterations of the `/loop` ultra-review of the family-chores codebase. The loop runs until agents converge (no new findings).

## How to use this file

On loop wakeup (no conversation context), read this file first. It tells you:
- What iteration we're on
- What's already been covered
- What areas to focus on next
- The accumulated findings register

After the new iteration:
- Add new findings to the register (deduped against existing)
- Bump the iteration counter
- Update "next focus" with what's still under-explored
- Decide quorum: if the new iteration adds <3 fresh findings, write the final doc and stop the loop

### Iter 1 HIGH validations (confirmed)

All 5 HIGH findings confirmed against actual code:
- **D-1** (multi-day calendar events dropped): CONFIRMED. `service.py:168-181`. Bucketing only by `event.start.date()` stores `[]` under days 2..N of a span. Cache hit on day 3 returns empty, never re-fetches.
- **D-2** (redemption tz drift): CONFIRMED. `week_anchor` from `local_today(tz)`, but compared against naive-UTC `Redemption.requested_at`. Window-edge drift up to 7h (LA) / 14h (NZ).
- **H-2** (stale UID write-back lost): CONFIRMED. `bridge.py:283` commits at end; per-instance failure mid-loop rolls back already-claimed UIDs. **Bridge actively creates duplicate todos between reconciler runs.** Severity nudge: keep HIGH but note retry-loop amplifies bug.
- **H-6** (reconciler races bridge): CONFIRMED. Reconciler opens own session without `_flush_lock`. Concrete race: bridge `add_item` → reconciler `remove_item` orphan deletion → freshly-added todo vanishes seconds after creation.
- **U-1 / S-1** (PIN no rate limit): CONFIRMED. Zero matches for rate-limit middleware codebase-wide. Argon2 cost = 4-digit brute force in ~7 min single-host. **Upgrade to CRITICAL for SaaS** path; keep HIGH for addon.

- **R-2** MED: Reconciler same anti-pattern as H-2 — single commit at end means partial-add failure rolls back earlier successful UID writes. Should commit per-member.

4. **Voice cheer on completion.** When `sound_default: true`, on completion, play a per-member-recorded "Good job, Alice!" — a 2-second clip the parent records once in Members tab. Hearing your own family say your name beats any synth bell.
5. **"Drawing of the day" canvas.** After a kid finishes all chores, they get an empty canvas. They scribble a doodle on the tablet, and it saves to `/data/doodles/<slug>/<date>.png`. Parents see a gallery; doodles appear on the parent's Today page as proof-of-life. No upload endpoint = stays on-device.

### NEW parent-relief features

1. **Bulk-approve from notification.** When 3+ approvals pile up (verified by `pending_approvals > 2`), HA Companion push notification: "Alice has 3 chores waiting." Notification action "Approve all" calls `/api/admin/instances/approve-bulk` with a 5min undo window. (Builds on existing N-7 idea.)
2. **"Quiet hours" auto-skip.** Sunday — parent taps "Lazy Sunday" → all chores marked skipped, no streak break, no missed-shame. Implementable as a household-level "today is a rest day" flag.
3. **Smart chore reordering by routine.** Currently chores list in creation order. Add `time_of_day` (breakfast/dinner/bedtime — matches N-15) and the kid's MemberView auto-sorts to current-time-of-day-first. Parent never re-sorts.
4. **"Family digest" Sunday email/notification.** Auto-generated weekly recap: "Alice 7-day streak, Bob 4, Carol 6. Top earner this week: Alice with 47pts. Most-completed chore: Tidy bedroom. Photo carousel of any kid-drawn doodles." Parent reads it Sunday morning over coffee.
5. **Audit-log undo for parents.** Wrong approval? "Approve" is a one-way trigger today. Add a 60s "Undo approve" toast in Approvals tab, just like the kid's undo on completion. Saves a parent from "oh wait I meant to deny that."
